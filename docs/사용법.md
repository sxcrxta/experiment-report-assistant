# 사용법 — 실행 · 백업 · 복구

개인 사용 전제다. 공개 배포·코드 서명·공증은 범위 밖이다 ([Q-22]~[Q-24]).
**macOS 에서 소스로 실행한다.** 한컴오피스 한글 for Mac 이 저장한 **HWPX 만** 다룬다.

> 이 프로그램은 보고서를 **읽기만 한다.** 메모를 넣지도, 검토본을 만들지도, 원본을 고치지도 않는다.
> 수정은 언제나 한글에서 직접 한다.

---

## 1. 실행

```
npm install          처음 한 번
npm run dev          개발 모드로 실행
```

`npm run dev` 가 Electron 창을 띄운다. 창이 뜨지 않으면 `npm run check` 로 먼저 확인한다.

```
npm run check        경계 → 타입 → 린트 → 테스트 (전부 통과해야 한다)
npm run build        위 검사를 거친 뒤 out/ 에 빌드
npm run preview      빌드된 결과로 실행
```

### 터미널 없이 쓰기 — `.app` 만들기

```
npm run package      검사 → 빌드 → .app 묶기 (몇 분 걸린다)
```

결과는 **`release/mac-arm64/experiment-agent.app`** 이다. Finder 에서 `응용 프로그램` 으로 끌어다 놓으면
그 뒤로는 더블클릭으로 연다. Finder·Dock 에는 **실험보고서 학습 보조** 라는 이름과
초록 바탕에 흰 보고서·물음표 아이콘으로 보인다.
파일 이름(`experiment-agent.app`)은 바꿔도 되지만, **앱 안쪽 이름은 바꾸지 않는다** (아래).

`release/` 는 git 에 올리지 않는다.

| 알아 둘 것 | 왜 |
| --- | --- |
| 이 맥에서만 돈다 | 인증서 서명·공증을 하지 않는다 ([Q-22]~[Q-24]). 다른 맥으로 옮기면 Gatekeeper 가 막는다 |
| 데이터는 그대로다 | `.app` 으로 써도 `~/Library/Application Support/experiment-agent/` 를 그대로 연다. 터미널로 쓰던 기록이 이어진다 |
| 앱 이름은 ASCII 로 둔다 | `electron-builder.yml` 의 `productName` 을 한글로 바꾸면 **켜자마자 조용히 죽는다.** 겪어 보고 `tests/packaging.test.ts` 로 막아 두었다 ([Q-31]) |
| 자동 업데이트는 없다 | 고친 뒤에는 `npm run package` 를 다시 돌리고 `응용 프로그램` 의 것을 덮어쓴다 |
| 아이콘을 바꾸려면 | `build/icon.py` 를 고치고 `python3 build/icon.py` 로 다시 그린다. 그림 파일을 주워 오지 않고 코드로 그린다 (색은 화면의 `--primary` 와 같은 값) |

### 처음 열었을 때

빈 화면에 **남은 설정**이 표시된다. 세 가지다.

| 단계 | 하는 곳 | 필수 |
| --- | --- | --- |
| 보고서 불러오기 | 사이드바 제목 옆 `＋` | 필수 |
| OpenRouter 키 등록 | 오른쪽 위 ⚙ 설정 | **선택** |
| 심층 검토 준비 (Claude Code) | 오른쪽 위 ⚙ 설정 | **선택** |

키를 등록하지 않아도 보고서 등록·저장 감지·버전 기록·평가 지침·자기평가·기존 피드백 조회·
개인화 관리는 그대로 쓸 수 있다. **막히는 것은 AI 검토 요청뿐이다.** 오프라인일 때도 같다.
Claude Code 가 없으면 **심층 검토만** 막히고 빠른 검토는 그대로 된다.

키는 macOS 키체인에만 들어간다. 설정 파일·DB·로그·빌드 결과에 쓰지 않고, 화면으로 되돌려 주지도 않는다.

### 쓰는 순서

1. HWPX 를 고른다. 과목은 **적어도 되고 비워도 된다** ([Q-52], 마지막에 쓴 과목이 채워져 있다. 나중에 평가 지침 탭에서 고친다). 모아 둔 평가 지침이 있으면 불러오기 창에서 **함께 고를 수 있다**(선택).
   불러오면 바로 `검토·다듬기` 탭으로 간다
2. 한글에서 보고서를 쓰고 저장한다 → 앱이 저장을 감지해 버전을 남긴다.
   바뀐 글이 있으면 검토 화면 위에 `방금 저장 · 바뀐 문단 N개` 가 뜨고, **`바뀐 부분 검토` 한 번**으로 요청할 수 있다 ([Q-51])
3. `검토·다듬기` 탭 맨 위 칸에 **"고찰 부분 피드백해줘" 처럼 적거나**, 아래 추천 요청(전체·바뀐 부분·큰 제목)을 누른다 ([Q-44], [Q-45])
   - 아래 목차 버튼은 **고르기만** 한다. 큰 제목을 누르면 가·나 같은 하위 항목이 펼쳐진다. 고른 뒤 `요청` 을 누른다
     (칸에 `힌트 줘`, `꼼꼼하게` 를 덧붙일 수 있다). 목차는 AI(Claude 먼저)가 나누고, 안 되면 번호 제목으로 나눈다 ([Q-47])
   - 알아듣는 말: `전체`, `바뀐 부분`, `3번 문단`, 제목 이름(`고찰`, `실험 결과` — "8. …고찰" 이면 9번 제목 전까지)
   - 같은 이름의 소제목이 여러 곳이면 고르지 않고 알린다. `실험 결과의 측정값` 처럼 윗제목을 붙인다
   - 말에 `힌트`·`설명`·`질문` 을 넣으면 그 단계로, `꼼꼼하게` 를 넣으면 심층 검토로 요청한다.
     없으면 앱이 정한 단계·빠른 검토를 쓴다 (단계 순서는 여전히 앱이 지킨다)
   - 짧은 수정 예시는 요청 칸으로 열리지 않는다. 피드백 카드에서 직접 요청한다
   - 아직 쓰지 않은 부분은 요청할 수 없다 (먼저 한글에서 쓰고 저장한다)
   - 같은 탭 맨 위 `검토 | 다듬기` 로 바꾸면 **적은 글을 보고서 문체로 다듬는다** ([Q-43], [Q-46]).
     요청 칸에 `다듬어줘: 적은 내용` 이라고 써도 다듬기로 넘어간다. 결과는 `복사` 해서 한글에 붙인다
   - 툴바 `◧` 를 누르면 한글 옆에 좁게 붙는 **보조 창**이 된다 (늘 위에 뜬다)
   - PDF 로 내보낼 필요는 없다. 앱은 HWPX 만 읽는다
4. 피드백마다 내 판단(동의/부분 동의/반박/이해되지 않음/수정 완료)을 남긴다. 누르면 바로 저장된다(반박만 사유를 받는다)
5. 제출하기 전에 `평가 지침` 탭에서 `양식 점검` 을 누른다 (선택, 아래 "평가 지침 = 제출 점검표")
6. 성장 기록 탭에서 누적된 관찰과 요약을 본다

검토·다듬기는 평가 지침을 쓰지 않는다. 지침을 고르지 않아도 검토는 그대로 된다 ([Q-48]).

**개요 탭**에는 본문을 늘어놓지 않는다. 저장할 때마다 AI(OpenRouter 의 Gemma)가 만든
**한 문단 요약**과 체크포인트만 둔다. 어느 모델이 썼는지 요약 옆에 적힌다.
오프라인이거나 OpenRouter 키가 없으면 요약이 만들어지지 않고, 그 사실만 적힌다.
본문은 한글에서 본다. 앱은 전문을 보여 주지 않는다 ([Q-45]).

## 2. 데이터가 있는 곳

| 무엇 | 위치 |
| --- | --- |
| 보고서·버전·지침·피드백·개인화 기록 | `~/Library/Application Support/experiment-agent/data.sqlite` |
| 체크포인트 (원본 HWPX 사본) | `~/Library/Application Support/experiment-agent/checkpoints/` |
| 로그 | `~/Library/Logs/experiment-agent/` |

앱 안에서도 확인할 수 있다: **설정 → 앱 정보와 저장 위치**, 또는 첫 실행 안내의 "기록이 저장되는 위치".

원본 HWPX 는 이 폴더에 들어가지 않는다. 사용자가 둔 자리에 그대로 있다.
앱은 그 **경로**를 기억할 뿐이다.

## 3. 백업

앱을 **끈 상태에서** 아래 폴더를 통째로 복사한다.

```
~/Library/Application Support/experiment-agent/
```

`data.sqlite` 와 `checkpoints/` 가 함께 있어야 한다. 하나만 복사하면 기록과 사본이 어긋난다.
켜 둔 채로 복사하면 SQLite 가 쓰는 도중일 수 있다.

원본 HWPX 는 따로 백업한다. 이 프로그램의 백업 범위가 아니다.

## 4. 복구

### 기록 전체 되돌리기

앱을 끄고, 백업해 둔 폴더를 위 경로에 그대로 되돌려 놓는다. 다음 실행에서 그 시점의 기록으로 열린다.

### 보고서를 예전 시점으로 되살리기

개요 탭의 체크포인트 목록에서 `되살리기` 를 누른다.
저장 위치를 묻고 **새 파일**로 쓴다. **지금 쓰고 있는 원본은 건드리지 않는다.**

체크포인트는 두 가지다.

- **최초본** — 보고서를 처음 불러올 때 자동으로 남는다
- **직접 남김** — 개요 탭에서 `지금 저장` 을 누른다. 이름(예: "제출 전")은 비워도 되고, 비우면 `버전 N 시점` 이 된다

### 문서 경로를 잃었을 때

다른 이름으로 저장했거나, 폴더를 옮겼거나, 지웠으면 감시를 멈추고 사이드바에
`파일 없음` 배지가 뜬다. 개요 탭에서 `새 위치 선택` 으로 새 위치를 알려 주면
기존 버전·지침·피드백 기록이 **같은 문서로 이어진다**.

비슷한 다른 파일을 앱이 임의로 찾아 붙이지 않는다.

## 5. 업데이트

```
git pull
npm install          package.json 이 바뀌었을 때만
npm run check        통과하는지 먼저 확인
npm run dev          터미널에서 쓸 때
npm run package      .app 으로 쓸 때 — 묶은 뒤 `응용 프로그램` 의 것을 덮어쓴다
```

DB 스키마가 바뀌었으면 첫 실행에서 마이그레이션이 자동으로 돈다.
마이그레이션은 순서대로 한 번씩만 적용되고, 실패하면 통째로 되돌아간다.
**업데이트 전에 3번의 백업을 권한다.**

## 6. 예외 상황

아래는 모두 **정상 경로**로 처리한다. 앱이 멈추거나 조용히 실패하지 않는다.
괄호 안은 그 동작을 고정한 테스트다.

| 상황 | 어떻게 되는가 | 테스트 |
| --- | --- | --- |
| 저장 중이거나 교체 중인 파일 | 크기가 안정될 때까지 기다렸다 읽는다. 한 번 실패했다고 깨졌다고 하지 않는다 | `watcher` · `integration/v1-hangul-save` |
| 빈 문서 | 등록은 되지만 검토 요청은 막는다 (선행 작성 보장) | `documents` · `rubric` |
| 표만 있는 문서 | 표 안 문단도 검토 대상이다. 글자 없는 빈 표만 있으면 요청을 막는다 | `table-only-document` |
| 저장 직후 미리보기 | 파일 해시가 기록과 다르면 서식을 만들지 않고, 새 버전을 기록하면 다시 읽는다 ([Q-39]) | `hwpx-preview` |
| 서식을 읽지 못함 | 안내를 적고 기록된 문단으로 고르기·검토를 그대로 한다 | `hwpx-preview` · `review-panel` |
| 지원하지 않는 그림 | 그 자리에 표시할 수 없다고 적는다. 외부 그림은 열지 않는다 | `hwpx-preview` |
| 그림이 너무 크거나 많음 | 총량까지만 보내고 몇 장을 보냈는지 요청에 적는다 | `review-images` |
| 앱이 모르는 수식 문법 | 그 수식만 스크립트 원문으로 보여 준다. 반쯤 조판하지 않는다 | `hwp-equation` |
| 오프라인 | **AI 검토 요청만** 막고 이유를 적는다. 나머지는 그대로 | `e2e-flow` · `review-stage` |
| 요약을 만들지 못함 | 조용히 지나가고 목록에 그 사실만 적는다. 저장 기록은 그대로다 | `document-summary` |
| 요약이 형식을 어김 | 정해진 횟수만 다시 묻고 저장하지 않는다. 원문을 요약인 척 보여 주지 않는다 | `document-summary` |
| 키 미등록 | 요청 바만 잠기고 설정으로 안내한다 | `gemma` · `keychain` · `first-run` |
| OpenRouter 오류·한도 초과 | 401/402/429/5xx 를 구분해 안내한다. 원문을 결과인 척 보여 주지 않는다 | `gemma` |
| 스키마 위반 응답 | 정해진 횟수만 재시도하고 실패를 그대로 알린다 | `model-schema` · `review-request` |
| 문단 분할·병합 | 새 UUID 를 주고 기존 UUID 와의 관계를 기록한다 | `track` · `documents` |
| 문장 앵커 유실 | 다른 문장에 자동으로 붙이지 않고 사용자 확인을 기다린다 | `sentence-anchor` · `review-stage` |
| 다른 이름·다른 폴더로 저장 | 감시를 멈추고 알린 뒤 재선택을 받는다 | `watcher` · `documents` |
| 파일 접근 권한 거부 | 재선택을 요청한다. 전체 디스크 접근 권한은 요구하지 않는다 | `documents` |
| iCloud 에 있고 아직 내려받지 않음 | 내려받은 뒤 다시 시도하라고 알린다 | `documents` · `watcher` |
| 지침 초안 제안이 형식을 어김 | 정해진 횟수만 다시 묻고 실패를 알린다. 원문을 초안인 척 보여 주지 않는다 | `rubric-suggest` |
| 제목·안내 문구가 없어 제안 근거가 없음 | 모델을 부르지 않고 직접 입력을 권한다 | `rubric-suggest` |
| Claude Code 가 없거나 로그인 안 됨 | **심층 검토만** 잠기고 이유를 적는다. 빠른 검토는 그대로 | `claude-path` · `review-depth` |
| 심층 검토가 오래 걸림 | 정해진 시간이 지나면 중단하고 알린다. 자식 프로세스를 남기지 않는다 | `claude-code` · `integration/v2-claude-code` |
| 심층 검토 중단 | 심층 검토가 도는 동안만 요청 바(재검토는 카드)에 `중단` 이 보인다. 프로세스를 정리한다 | `claude-code` · `review-panel` |
| 심층 재검토 대상 문단이 사라짐 | 다른 문단에 임의로 붙이지 않고 알린다 | `review-depth` |

## 7. 평가 지침 초안 제안 (보조 기능)

조건을 처음부터 다 적기 번거로우면 보고서 뼈대로 초안을 받는다. 두 곳에서 할 수 있다.

- 평가 지침 탭 `＋ 새 지침` → **`보고서 구조로 채우기`**: 지금 고른 보고서로 조건 초안을 채운다.
  AI 를 쓸 수 없으면 불러올 때 만들어 둔 뼈대 초안으로 채운다.
- `이 보고서에서만 고치기` 편집기 → **`초안 제안받기`**

공통으로:

- **보내는 것은 문서 뼈대뿐이다** — 제목, 표·그림 설명, "…하시오" 같은 양식 안내 문구,
  그리고 표·수식·본문 문단의 **개수**. **보고서 본문은 보내지 않는다.**
- 이미 적어 둔 조건을 **지우지 않는다.** 아래에 덧붙일 뿐이다.
- 받은 초안은 **저장되지 않는다.** 고친 뒤 저장(모음) 또는 확정(이 보고서)해야 남는다.
  확정 전 초안으로는 양식 점검을 하지 않는다.
- 오프라인이거나 키가 없으면 AI 초안만 안 된다. 직접 입력·저장·확정은 그대로 된다.
- 문서에 제목도 안내 문구도 없으면 모델을 부르지 않고 직접 입력을 권한다.

제안은 어디까지나 보조다. 무엇을 조건으로 삼을지는 사용자가 정한다 (PRD 4.1).

## 8. 심층 검토 (Claude 모드) — 선택

기본은 빠른 검토다. 요청 칸에 **`꼼꼼하게`**(또는 `자세히`, `심층`)를 넣으면 심층 검토로 요청한다 ([Q-44]).

| 깊이 | 누가 | 무엇을 보는가 |
| --- | --- | --- |
| 빠른 검토 | OpenRouter 의 Gemma | 양식·항목 누락, 문장·문단 단위 질문과 힌트, 표·그림·출처의 기본 확인 |
| 심층 검토 | 이 맥에 설치된 **Claude Code** | 과학적 정확성과 복잡한 논리, 결과–고찰–결론의 연결, 전체 구조, 반박의 재검토 |

### 준비

1. 터미널에서 `claude auth status` 로 로그인되어 있는지 본다. 아니면 `claude auth login`
2. 앱의 ⚙ 설정에서 **심층 검토 (Claude 모드)** 구역을 본다
3. 자동으로 찾지 못하면 터미널의 `which claude` 결과를 **경로 지정** 칸에 넣는다
   (Finder 로 띄운 앱은 로그인 셸의 PATH 를 물려받지 못해 못 찾을 수 있다)

Anthropic API 키는 **필요 없다.** 이미 로그인된 Claude Code 를 부를 뿐이고,
앱이 Claude API 를 직접 호출하는 코드는 없다.

### 쓸 때

- 요청 칸에 `꼼꼼하게` 를 넣는다. 쓸 수 없으면 요청하지 않고 이유가 뜬다
- 빠른 검토보다 오래 걸린다 (한 문단에 20초 안팎). 급하면 `심층 검토 중단` 을 누른다
- 한 번에 하나만 돈다. 요청이 겹치면 차례로 처리한다
- 피드백 카드의 **`심층 재검토 요청`** 은 그 피드백과 **내가 남긴 판단**을 함께 보내 다시 본다.
  원 피드백과 내 판단은 지워지지 않고, 단계도 새로 열리지 않는다
- 성장 기록 탭의 **`심층 분석 요청`** 도 같은 조건에서 열린다

### 나가는 것

빠른 검토와 **같다**: 고른 문단과 그 앞뒤 문단, 문서 종류, 승인한 개인 지침,
(재검토라면) 원 피드백과 내 판단. **평가 지침은 보내지 않는다** ([Q-48]).
문서 파일·문서 전체·파일 경로·과목도 보내지 않는다. (빠른 검토는 여기에 그림이 더해진다 — 8-1)
검토 내용은 `~/.claude/projects` 에도 남지 않는다 (`--no-session-persistence`).

## 8-1. 검토로 나가는 그림

검토를 요청하면 **보고서의 그림 전체**가 글과 함께 OpenRouter 로 나간다 (사용자 결정, [Q-38]).
그래서 "표·그림 설명" 관점이 캡션 글만 보지 않고 실제 그림을 보고 판단한다.

- 그림은 HWPX 안에 있던 그대로 나간다. 앱이 다시 그리거나 고치지 않는다.
- 한 번에 나가는 양을 묶어 둔다: 개당 4MB · 총 12MB · 40장. 넘치면 앞에서부터 담다가 멈추고,
  몇 장을 보냈는지 요청에 그대로 적힌다.
- 그림이 없거나 읽지 못하면 글만으로 검토한다.
- **심층 검토(Claude 모드)는 그림을 보내지 않는다.** 글만 본다.
- 사진에 사람이 찍혀 있으면 그것도 함께 나간다. 원하지 않으면 한글에서 그 사진을 뺀 뒤 저장한다.

## 8-2. 보고서 요약으로 나가는 것

보고서 목록의 한 문단 요약을 만들 때는 **본문 전체**가 OpenRouter 로 나간다 (사용자 결정, [Q-36]).
검토 요청은 여전히 고른 범위와 그 앞뒤 문맥만 보낸다. 요약만 예외다.
무엇이 나가는지는 `src/app/document-summary.ts` 의 `toSummaryPayload` 한 곳에서 확인할 수 있다.
요약을 만들고 싶지 않으면 설정에서 OpenRouter 키를 지우면 된다 — 요약만 만들어지지 않고
나머지 로컬 기능은 그대로 쓸 수 있다.

## 삭제 ([Q-42])

| 무엇을 | 어디서 | 함께 지워지는 것 |
| --- | --- | --- |
| 보고서 | 개요 탭 `보고서 삭제` | 이 앱의 버전·피드백·내 판단·자기평가·체크포인트 사본. **한글 원본 파일은 그대로** |
| 체크포인트 | 개요 탭 체크포인트 옆 `삭제` | 보관 사본. **최초본은 지울 수 없다** |
| 피드백 | 검토 탭 카드를 펼쳐 `삭제` | 거기 남긴 내 판단, 성장 기록의 그 관찰 |
| 평가 지침 | 평가 지침 탭 모음 카드 `삭제` | 모음에서만 빠진다. 적용했던 보고서의 지침은 남는다 |
| 개인화 지침·자기평가·기록 | 성장 기록 탭 각 항목 `삭제` | 그 항목 |

모두 확인 창을 거치고, 되돌릴 수 없다.

## 평가 지침 = 제출 점검표 ([Q-48])

- 검토·다듬기는 평가 지침을 쓰지 않는다. 대신 검토 화면 맨 위의 **문서 종류**(AI 가 짐작, `고치기` 로 직접 수정)에 맞춰 본다.
- 평가 지침 탭에는 **반드시 충족해야 하는 조건**을 한 줄씩 적는다 (예: 고찰 부분은 200자 이상이어야 한다).
  글자 수는 앱이 목차 항목마다 세어 AI 에 함께 넘기므로, 글자 수 조건도 그대로 적으면 된다 ([Q-50]).
  모음에서 골라 적용(확정)한 뒤 `양식 점검` 을 누르면 AI 가 보고서 전체를 읽고 조건마다 **충족도 %** 와
  근거·문단 번호를 보여 준다. 맨 위의 전체 충족도는 조건별 % 의 평균이다 ([Q-49]).
- 점검은 누를 때만 한다. 보고서를 다시 저장하거나 점검표를 바꾸면 "낡았다" 고 알려 준다.
- 점검할 때는 보고서의 글 전체가 AI 로 나간다.
