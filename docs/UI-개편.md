# UI 개편

2026-09-12 사용자 제공 `stitch_codex`의 세 디자인을 기존 기능에 통합했다.
보고서 사이드바와 문서 작업 공간 / 평가 지침 / 검토 피드백 탭을 공통 껍데기로 사용한다.
화면은 실제 로컬 IPC 데이터로 채우며 디자인의 예시 보고서·수치는 앱에 넣지 않았다.

## 2026-09-12 반영 결과

- `_1`: 문단 목록·검색·변경 필터, 실제 버전 기록, 체크포인트 저장·새 파일 복구.
- `_2`: 과목 입력, 지침 카드 편집·중요도·순서 변경, 고정된 초안 저장/확정 영역.
  평가 지침은 독립 탭으로 열고, 탭/보고서를 전환해도 미저장 입력을 유지한다.
  불러오기 실패 시 오류와 다시 열기 버튼을 표시한다.
- `ai`: 검토 요청 바, 상위 5개 카드, 단계 표시·근거·동등한 반응 버튼의 기존 구조를 적용했다.
  항목 경계 편집은 접어 두어 카드에 집중할 수 있다.
- 외부 CDN·글꼴 없이 시스템 한글 글꼴과 로컬 CSS를 사용한다. 원본 HWPX 쓰기는 추가하지 않았다.
- 이 디자인 통합만으로는 8단계 완료를 주장하지 않았다.
- `초안 제안 · 준비 중` 자리는 이후 `초안 제안받기` 로 채웠다 (PRD 4.1 보조 기능).

## 2026-09-12 성장 기록 탭 (8단계와 함께)

- 네 번째 탭 `성장 기록`을 같은 껍데기에 연결했다 (`views/growth.ts`).
  요약 · 관점별 집계 · 승인한 개인화 지침 · 자기평가 · 문서 버전 근거를 한 화면에 둔다.
- 반응과 자기평가는 검토 피드백 카드 안에서 바로 저장한다 (`views/reaction.ts`). 더 이상 비활성이 아니다.
- 피드백 카드에 **반복 관찰 근거**를 항상 붙인다. 근거가 없으면 없다고 적는다 (T-8).
- 성장 요약은 이 탭에만 둔다. 내보내기 경로를 만들지 않았다.

검증: `npm run build` 성공(계층·타입·린트, 29개 파일의 568개 테스트).
빌드된 렌더러를 실제 저장소와 분리한 메모리 예시 브리지로 확인했다.
1280px 및 1000px 너비의 배치, 지침 열기/재시도/입력 유지/초안 저장/확정,
변경 문단 필터, 피드백 펼침, 빈 상태·오프라인·경로 유실 표시를 확인했다.
이 검증은 Electron의 실제 IPC·파일 선택·키체인 E2E를 대신하지 않는다.
네이티브 화면 검증은 macOS 접근성·화면 기록 권한 연결이 되지 않아 남아 있다.

## Stitch

| | |
| --- | --- |
| 프로젝트 | `projects/6229182317068814030` — 실험보고서 학습 보조 |
| 디자인 시스템 | `assets/9942744392607305788` |

화면을 새로 만들 때는 반드시 `designSystem: "assets/9942744392607305788"` 을 지정한다.
지정하지 않으면 기본 디자인 시스템이 적용되어 톤이 어긋난다.

### 디자인 시스템에 박아 둔 것

폰트는 **Noto Sans**. Stitch 폰트 목록에 Apple SD Gothic Neo 나 Pretendard 가 없어
한글을 제대로 지원하는 유일한 선택이다. 실제 앱으로 옮길 때 시스템 폰트로 바꾼다.

강조색 `#2E6F6A` (차분한 청록), 중성 회색 기반, 라운드 8px.

제품 원칙을 `designMd` 에 넣었다. 이게 화면 품질을 좌우한다.

- **빨강은 시스템 오류에만.** AI 피드백에 쓰면 지적당하는 느낌이 되어 제품 목적에 어긋난다
- **사용자 반응 4종이 대등한 무게.** '반박' 이 위험한 행동처럼 보이면 안 된다. 반박은 권장되는 행동이다
- **단계적 잠금.** 질문 → 약한 힌트 → 강한 힌트 → 설명 → 수정 예시. 예시는 명시 요청 시에만
- **지침 확정 전에는 AI 가 동작하지 않는다**는 사실이 화면에 드러나야 한다
- **상위 5개만 먼저**, 나머지는 '더 보기'
- **오프라인이면 AI 검토만 막힌다.** 나머지는 정상으로 보여야 한다
- 상태 변형(빈 상태·오프라인·경로 유실·로딩)을 항상 함께 만든다

## 코드로 옮길 때의 제약

### CSP

렌더러의 CSP 가 `default-src 'self'` 다 (`src/renderer/index.html`).
**외부 폰트·이미지·스크립트를 불러올 수 없다.** Stitch 결과를 그대로 붙이면 깨진다.

- Google Fonts `@import` / `<link>` 제거 → 시스템 폰트 스택으로 대체
  `-apple-system, BlinkMacSystemFont, 'Apple SD Gothic Neo', 'Pretendard', sans-serif`
- 외부 이미지 URL 제거 → 인라인 SVG 나 data URI
- CDN 스크립트 제거

### 계층 경계

렌더러는 파일·네트워크에 직접 닿지 않는다 (`CLAUDE.md` §7).
화면은 `window.agent` (preload 브리지)만 쓴다. `tools/boundaries.ts` 가 강제한다.

### 적용 시점

5단계의 데이터 구조가 확정된 뒤, 2026-09-12 사용자 요청으로 세 화면과 공통 껍데기를 통합했다.
성장 기록은 8단계 구현 이후에 연결한다.

## 화면별 프롬프트

다시 뽑거나 변형을 만들 때 쓴다. 요령:

- **한 번에 한 화면.** 여러 화면을 한 프롬프트에 넣으면 뭉개진다
- **숫자를 준다.** "사이드바 240px", "435문단 중 1개 변경" 처럼 실제 데이터에 가까운 값을 넣으면
  레이아웃이 현실적으로 나온다
- **상태 변형을 따로 요청한다.** 이 앱은 예외 상태가 많다
- 마음에 안 들면 `generate_variants` 로 같은 화면의 여러 안을 뽑아 비교한다

# 구현 스펙 (Stitch 결과에서 확정)

`docs/design/*.html` 이 Stitch 가 만든 원본이다. **그대로 복사하지 말고** 아래 스펙을 따른다.
원본은 참고용이며, 아래는 원본을 읽고 이 앱에 맞게 정리한 것이다.

## 색 토큰

Stitch 가 화면마다 조금씩 다른 값을 냈다(`#F4F4F7` / `#f7f7f8` / `#F8F9FA`).
**아래 값으로 통일한다.** 한 곳에 CSS 변수로 정의하고 화면은 변수만 쓴다.

```
--primary:                  #2E6F6A   강조. 선택 표시, 주 버튼, 활성 탭 밑줄
--primary-container:        #E0EFED   강조의 연한 배경. 선택된 항목 배경
--surface:                  #FFFFFF   본문 바탕
--surface-container-low:    #F7F7F8   사이드바 바탕
--surface-container:        #F1F1F3   카드 바탕
--surface-container-high:   #EBEBED   구분된 영역
--surface-container-highest:#E4E4E7   칩, 배지 바탕
--border:                   #E4E4E7   1px 구분선
--text:                     #1C1C1E   본문 글자
--text-muted:               #6B6B70   메타 정보, 흐린 문단
```

**빨강은 시스템 오류에만 쓴다.** Stitch 원본에 `#ff5f56` 이 있는데 그것은 macOS 창
신호등 버튼을 그린 목업 장식이다. 실제 창 테두리는 Electron 이 그리므로 **구현하지 않는다.**

## 글꼴

Stitch 는 `Public Sans` 를 썼지만 **쓰지 않는다.** 한글 글리프가 없어서 한국어가 어차피
대체 글꼴로 떨어진다. CSP 상 외부 글꼴도 못 받는다 (`default-src 'self'`).

```css
font-family: -apple-system, BlinkMacSystemFont, 'Apple SD Gothic Neo', 'Pretendard', sans-serif;
```

아이콘도 `Material Symbols Outlined` 를 받지 말고 인라인 SVG 로 그린다.

## 모서리와 선

- 모서리: 8px
- 구분선: 1px, `--border`
- 그림자: 쓰지 않는다. 경계는 선으로만 만든다

## 피드백 카드 (5단계)

`docs/design/3-피드백탭.html` 참고.

**접힌 카드** 한 줄: 대상 배지("문단 142") · 관점 칩 · 한 문장 요약 · 오른쪽 펼치기 화살표

**펼친 카드**
1. **단계 표시기** — 질문 → 약한 힌트 → 강한 힌트 → 설명 → 수정 예시.
   현재 단계만 채워지고 다음 단계는 자물쇠로 잠긴 모습.
   **'수정 예시' 는 더 흐리게** 하고 옆에 작은 글씨 "직접 요청해야 열립니다".
2. **적용된 지침** — 회색 배지. 지침 제목과 중요도
3. **근거** — 두세 줄
4. **수정 전후** — 접힌 행
5. **반응 버튼 4개** — 동의 / 부분 동의 / 반박 / 이해되지 않음.
   **네 개가 같은 크기, 같은 색, 같은 테두리여야 한다.**
   '반박' 을 빨강이나 경고색으로 칠하지 않는다. 반박은 권장되는 행동이다
6. **자기평가 메모** — 한 줄 입력 칸

**목록 규칙** — 상위 5개만 보이고 나머지는 "나머지 N개 더 보기" 로 접어 둔다.
목록 위에 회색 글씨 "중요한 순서로 5개를 먼저 보여 드립니다."

## 검토 요청 바 (5단계)

- 범위 세그먼트: 문장 / 문단 / 보고서 항목 / 전체
- 관점 칩(다중 선택): 양식 준수 · 표·그림 설명 · 참고문헌 · 과학적 정확성 ·
  내용의 논리 · 글의 구조 · 문장 표현
- 오른쪽 끝 "검토 요청" 주 버튼
- 오프라인이거나 키가 없으면 **이 바만** 비활성이 되고 이유를 옆에 적는다.
  나머지 화면은 그대로 쓸 수 있어야 한다

## 앱 껍데기 — 별도 UI 통합으로 반영

Stitch 디자인은 왼쪽 사이드바(보고서 목록)와 머리말 탭 4개
(문서 / 평가 지침 / 검토 피드백 / 성장 기록)를 공통 껍데기로 쓴다.

5단계의 검토 요청 바와 카드를 유지하면서, 별도 UI 통합 작업으로 세 탭을 먼저 연결했고
성장 기록 탭은 8단계 구현과 함께 붙였다 (`STAGE_TASKS.md`의 "UI 통합" 항목).
